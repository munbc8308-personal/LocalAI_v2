# 디버깅

원칙: 원인을 증명하기 전에는 고치지 않는다. 증상을 덮는 수정(예외 삼키기, 재시도 추가, 값 하드코딩)은 하지 않는다.

## 1. 증상 고정
- 정확한 오류 글, 재현 단계, 기대한 동작과 실제 동작을 한 줄씩 적는다.
- 재현할 수 있으면 먼저 재현한다 (테스트·명령·로그). 못 하면 무엇이 없어서인지 적는다.

## 2. 가설
- 가능한 원인을 2~4개 적고, 각각 "참이면 보일 증거"를 적는다.
- 가장 싸게 확인할 수 있는 것부터 확인한다: 로그, 스택 트레이스의 맨 아래 내 코드 줄, 최근 변경(`git log -p -- 파일`), 입력값.
- 확인 결과로 가설을 지운다. 남은 하나가 증거와 모두 맞을 때 원인이다.

## 3. 고치기
- 원인이 있는 가장 좁은 곳을 고친다. 같은 원인이 다른 곳에도 있으면 함께.
- 싸게 만들 수 있으면 고치기 전에 실패하는 회귀 테스트를 만든다 (/tdd).
- 고친 뒤 재현 단계를 다시 돌려 사라진 것을 확인하고, 관련 테스트를 돌린다.

## 답 형식
원인(증거와 함께) → 고친 곳(`파일:줄`) → 확인한 방법과 결과. 확인하지 못한 것은 그렇다고 적는다.
