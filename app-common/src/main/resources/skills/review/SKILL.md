# 코드 리뷰

목표: 머지하면 실제로 터지는 문제를 찾는다. 취향·서식 지적은 하지 않는다.

## 대상 정하기
- 요청에 파일·커밋·브랜치가 있으면 그것. 없으면 `git diff HEAD`(작업 중 변경), 비었으면 `git diff HEAD~1`.
- 셸은 읽기만 한다 (`git diff`, `git log`, `git show`, 테스트 실행). 파일을 고치지 않는다.

## 보는 순서
1. 바뀐 줄을 읽고, 그 함수를 부르는 곳·부르는 함수까지 찾아 읽는다 (변경만 보면 맥락을 놓친다).
2. 각 변경에 대해 묻는다:
   - 정확성: 경계값(빈 값·null·0·최대), 반대 조건, 한 칸 차이, 예외 경로, 되돌리기.
   - 동시성: 공유 상태, 순서, 취소·시간 초과, 재시도 중복.
   - 자원: 닫지 않은 스트림·연결, 무한 반복, 큰 입력.
   - 계약: 부르는 쪽 가정이 깨졌는지, API·저장 형식이 바뀌어 옛 데이터가 깨지는지.
   - 테스트: 바뀐 동작을 테스트가 실제로 확인하는지.
3. 의심되면 확인한다: 코드를 더 읽거나, 테스트를 돌리거나, 작은 재현을 생각한다. 확인 못 한 것은 "가능성"으로 표시한다.

## 답 형식
찾은 것마다 한 덩어리, 심각한 것부터:
- `파일:줄` — 무엇이 틀렸는지 한 문장
- 터지는 상황: 어떤 입력·상태에서 무엇이 잘못되는지
- 고칠 방법: 가장 작은 수정

없으면 "찾은 문제 없음"과 무엇을 봤는지(파일·범위)만 적는다. 칭찬·요약·서식 지적은 넣지 않는다.
