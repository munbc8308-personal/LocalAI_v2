# 리팩터

규칙: 동작을 바꾸지 않는다. 버그를 발견해도 이 작업에서는 고치지 않고 따로 알린다.

## 순서
1. 범위: 바꿀 코드와 그것을 부르는 곳을 모두 찾는다 (`search_files`로 이름·문자열 사용처까지).
2. 기준선: 관련 테스트를 먼저 돌려 통과를 확인한다. 테스트가 없거나 약하면, 바꿀 동작을 고정하는 테스트를 먼저 더한다.
3. 작은 단계: 한 번에 한 가지(추출 하나, 이름 하나). 단계마다 컴파일·테스트.
4. 옛 것 지우기: 부르는 곳을 모두 옮긴 뒤 옛 함수·별칭을 지운다. 호환용 껍데기를 남기지 않는다(밖에 공개된 API가 아니면).
5. 마무리: 전체 관련 테스트를 다시 돌린다.

## 하지 않는 것
- 요청 밖의 파일 정리, 서식만 바꾸기, 새 추상화를 미리 만들기.
- 공개 API·저장 형식·설정 이름 바꾸기 (요청에 있을 때만, 그때는 옮기는 방법도 적는다).

## 답 형식
무엇을 어떻게 바꿨는지(파일별 한 줄), 돌린 테스트와 결과, 따로 발견한 문제.
