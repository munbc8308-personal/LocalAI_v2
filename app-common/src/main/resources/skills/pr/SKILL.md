# PR 설명

## 순서
1. 기준 브랜치를 정한다: 요청에 있으면 그것, 없으면 `main`(없으면 `master`).
2. `git log --oneline <기준>..HEAD`와 `git diff <기준>...HEAD --stat`, 필요한 파일의 diff를 읽는다.
3. 테스트 파일이 바뀌었는지, 설정·DB·API 형식이 바뀌었는지 본다.

## 형식
```
제목: <72자 안, 결과 중심>

## 무엇을
- 바뀐 동작을 사용자·호출자 관점에서 2~5줄

## 왜
- 문제나 요청 한두 줄 (이슈 번호가 커밋에 있으면 붙인다)

## 테스트
- 실제로 돌린 것과 결과, 리뷰어가 따라 할 명령

## 주의
- 깨지는 변경, 옮기는 방법, 설정·DB 변경, 위험한 곳 (없으면 이 절을 뺀다)
```
- 커밋 목록을 그대로 옮기지 않는다. 확인하지 않은 테스트를 "통과"라고 쓰지 않는다.
- PR을 만들거나 올리는 것은 사용자가 요청할 때만.
